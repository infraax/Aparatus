# M1 — local RWS runtime

A single-project kernel that enforces RWS 2.0 compile rules on one append-only chain.

## Build and test

```bash
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo build --workspace --locked      # binary: target/debug/apparatus
```

## On disk (`<project>/.apparatus/`)

```text
project.json    ProjectId, name, solo flag, default principal
cas/            sha256/ab/cd/<hex> bytes + ids/<artifact-id> pointer (write-once)
ledger.jsonl    one canonical-JSON receipt per line, hash-chained
HEAD            <last receipt id> <hash>
```

## Demo

```bash
apparatus rws init --solo                       # one owner: continuity, policy, execution, mandate_holder (M2)
apparatus rws ingest ./README.md --purpose corpus --tag C
apparatus rws policy agreement --asset demo     # M2: keep needs an agreement covering the asset (K-01)
apparatus rws queue keep --asset demo           # prints <item-id> queue_keep <hash>
apparatus rws event target_dropped --subject <item-id>
apparatus rws gate --item <item-id> --gate start --outcome go --evidence <artifact-id>
#   → REFUSED K-06 (keep never passes build gates), exit 2, refusal recorded on the chain
apparatus rws check                             # chain, CAS, roles, items, refusals, open failures
```

Without `--solo`, `init` binds only `continuity`; `queue keep` is then refused (R-09) until
`rws role-bind --role execution --principal <name>` is done. That refusal is intended.
M2 additions (agreement check, correction/review, writer lock): see `M2.md`.

## Commands

| Command | Kind written | Default signer role |
|---|---|---|
| `init [--solo] [--principal owner]` | `role_bind` (bootstrap) | continuity |
| `role-bind --role R --principal N [--kind human\|agent\|service\|external_model]` | `role_bind` | continuity |
| `ingest PATH --purpose S --tag A\|B\|C\|E\|NF [--classification ...] [--replica]` | `ingest` | execution |
| `queue keep --asset A` / `queue keep --item ID --to STATE` / `queue build --asset A` | `queue_keep` / `queue_build` | execution / policy |
| `gate --item ID --gate G --outcome O --evidence ART [--envelope E --required N] [--discharge N --agreement ID]` | `gate` | policy (handover: mandate_holder) |
| `means --envelope E --from S --to S\|spent --amount N [--item] [--gate] [--agreement]` | `means` | policy (spend: execution) |
| `event KIND --subject ID [--impact S] [--next-role R]` | `event` | execution |
| `advice --summary S` | `advice` | adviser/execution |
| `policy envelope\|agreement\|rule ...` | `policy` | continuity / all three / policy |
| `show ID`, `check`, `import-jsonl PATH` | — | — |

Global flags: `--project DIR`, `--as NAME`, `--role R`.
Exit codes: `0` ok, `1` error or integrity failure, `2` refused by an RWS rule.

## Import buffer

If `rws/receipts.jsonl` exists, `init` imports it once (all lines validate or nothing is
written), then renames it to `receipts.jsonl.imported`. `import-jsonl` refuses when the
chain already has a HEAD. `check` fails if a buffer sits next to a live chain.
Buffer `ingest` lines with outcome `admit` need their bytes already in `cas/`.
