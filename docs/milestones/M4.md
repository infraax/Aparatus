# M4 — conduits: ingest pipe, signals, replica backup, hooks

```text
agents → in/new/ ─┐                  ┌→ in/ok/ | in/refuse/ | in/quarantine/  (+ <name>.json)
clients → socket ─┴→ writer actor ───┼→ FileLedger + CAS
            ticker (every 60 s) ─────┴→ .apparatus/SIGNAL + dampened tickets
```

M3 stays: one daemon, one writer, tickets. M4 adds ordered streams on that writer. Keep working first; smarter later.

## Ingest drop-pipeline (keep, not project)

`<project>/.apparatus/in/{new,work,ok,refuse,quarantine}/`

- Agents only drop into `in/new/`. Write to a dotfile or another directory, then rename in. Dotfiles are ignored.
- Optional sidecar `<file>.rws.json` `{purpose, tag, classification, replica}`: write it **before** the file.
- Only the writer moves `new → work`, one file at a time, oldest first (mtime, then name). With a daemon, the
  `ingest` thread feeds one file per job (`--ingest-poll-ms`, default 1000), so client requests interleave with a
  long batch. Without a daemon, `apparatus rws ingest-dir` does the same under `.apparatus/LOCK`.
- Every file leaves `work/` for exactly one folder, with a `<name>.json` result beside it:

| Case | Outcome |
|---|---|
| New bytes | C-03 `admit` receipt → `ok/` `{status: admitted, receipt, artifact_id, digest, tag}` |
| No tag in sidecar | admitted as `C` + ticket `untagged ingest: <name>` |
| Empty file | C-03 `reject` receipt (reason `empty file`) → `refuse/` `{rule: C-03}` |
| Digest already admitted | idempotent no-op → `ok/` `{status: already_admitted, artifact_id}`; no receipt, no 2nd id |
| Chain refuses (any rule) | refusal event on the chain → `refuse/` `{rule, reason, refusal_event}` |
| Unreadable, bad sidecar, CAS/disk error | `quarantine/` `{reason}` + ticket `ingest quarantined: <name>` |

- `ingest_enqueue {path | content+name, purpose?, tag?, classification?, replica?}` (RPC, or `rws enqueue <file>`)
  writes into `in/new/` atomically; it does not ingest. The principal must be bound (X-10) like any write.
- Queue full (`--ingest-capacity`, default 256 files in `new/`) → `busy` plus **one** open ticket
  `signal: ingest queue full`; the tick closes it once the queue drains.

**Crash in `work/`.** A file found in `work/` is a leftover. The next step re-offers it once, guarded by
`work/.<name>.retry`. If that attempt dies too (panic, kill), the step after quarantines it with a ticket, so
a poison file cannot crash-loop the daemon. If the crash came after the CAS write but before the receipt, the
retry moves the unrecorded blob to `cas/orphans/` and admits cleanly. If it came after the receipt, the retry
sees the digest and settles the file as `already_admitted`. CAS writes are now tmp + hard-link, so a partial
blob never sits under its digest name. Bytes are admitted only by a receipt.

## Signals and failsafes

- Tick every `--signal-every` seconds (default 60; one at start): run `check`, write `.apparatus/SIGNAL`
  (JSON: `status`, `time_ms`, `queue_depth`, `in_work`, `quarantined`, `head_id`, `head_hash`, `receipts`,
  `open_tickets`, `causes`, `source`). A watchdog reads it without RPC.
- Each failing cause files a ticket `signal: <cause>` (a `report_back` event, X-12). **Damping:** while a
  ticket with that exact title is open, the cause files nothing more. When the cause is gone the tick closes
  the ticket (`report_back_resolved`, "green again"); a relapse files a fresh one. The daemon never exits.
- `rws signals` asks the daemon (or computes locally); exit 1 on `fail`. `rws signals --file` prints SIGNAL only.
- Background failures (pipe folder error, tick or ingest panic) → reload chain + one dampened ticket
  `apparatusd: … panicked|failing`. Request panics still reload + ticket as in M3.
- `busy`: the CLI retries a **read** once after 1 s. A busy write may still land — check `rws head`.

## Backup / restore (replica)

```bash
apparatus rws backup --to /backups/demo-2026-09-30       # daemon or local; DIR absent or empty
apparatus --project /tmp/empty rws restore --from /backups/demo-2026-09-30
```

- Backup runs in the one writer (daemon actor or local LOCK holder): copies `project.json`, `ledger.jsonl`,
  `HEAD`, `cas/` (not `orphans/`), re-verifies the copied chain against the live head, then writes
  `MANIFEST.json` last `{replica: true, created_ms, project_id, head_id, head_hash, receipts, files, note}`.
  No manifest = interrupted backup = not restorable. Nothing is written to the chain.
- Restore refuses a non-empty `.apparatus/` (never over a live HEAD) and a running daemon. It stages into
  `<project>/.apparatus-restore/`, opens it as a project (chain, replay of every rule, CAS digests), requires
  head == manifest head, then moves files in under the destination lock, `HEAD` last.
- A backup confers no rights (A-08). To record a restore drill, file `rws event restore-tested` yourself.

## Hooks (empty conduits)

Crate `apparatus-hooks`: `trait Hook: Send + Sync` with no-op defaults `after_receipt(&Receipt)`,
`after_refuse(rule, subject)`, `on_signal(&Signal)`, `after_backup(&Path)`. Ships `NullHook` (default) and
`LogHook` (`apparatusd --log-hook`, stderr). One hook per process, set with `Kernel::set_hook`. Hooks listen;
they never write the chain or veto. MCP notify, remote wake and object storage implement this later.
