# M6 — MCP bridge (issue #8): stdio transport, canister control plane

```bash
apparatus mcp serve --gate <mcp-gate canister id> [--key .ic-local/anker.key] [--url http://127.0.0.1:8080]
```

**How it is split**
- **Transport:** a stdio MCP server, `bins/apparatus-cli/src/mcp.rs`. It speaks JSON-RPC 2.0, one message per line, protocol `2025-06-18`, and answers `initialize`, `ping`, `tools/list` and `tools/call`.
- **Control plane:** the `mcp-gate` canister on the local replica (NAP-corpus `docs/ic/canisters/mcp-gate`, `MCP-GATE.md`). The Motoko canister does not speak MCP.
- **The kernel stays the only truth.** apparatusd stays the only writer, and the bridge adds no new logic to it.

**What happens on each `tools/call`**
1. The bridge computes `sha256` of the canonical JSON arguments.
2. It calls `check(tool, hash)` on the canister, signed with the anker key (`apparatus_ic::gate::check`).
3. The canister records an Event: `{tool, argsHash, allow|refuse, reason, caller}`.
4. Only on `allow` does the bridge run the tool.

**When a call is refused**
- An unreachable gate means refuse.
- An unknown tool means refuse. The default is refuse.

| Tool | Does | Writes |
|---|---|---|
| `chain_head` | apparatusd RPC `head` over the 0600 socket. Errors if no daemon is running | nothing |
| `ic_status` | replica status through ic-agent | nothing (unlike `rws ic status`) |
| `quarantine_scan` | parses `Cargo.lock` / `package-lock.json` / `pnpm-lock.yaml` and counts pins; no network | nothing; the lockfile is unchanged |

There are no `install_code`, `setAnker` or key-export tools. The canister refuses to register any tool that names those capabilities.

Suite: 96 → 100, all four gates green.

## Acceptance of #8: what is met and what is not

| #8 acceptance | Status |
|---|---|
| Claude Code can ingest a file and open a ticket through MCP | **not met**. The first tools are read-only by instruction. Write tools need a token model first |
| Wrong token → refused, no chain mutation | **partly met**: there is no per-client token. Instead, an unregistered tool is refused by the canister and recorded as an Event, and nothing is written. Per-client tokens are open |
| The daemon keeps running if an MCP client crashes | met by design. The bridge is a separate process that talks to the daemon over the socket. Not separately tested |
